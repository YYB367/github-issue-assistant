# V3 修改清单（2026-10-16）

今后每次版本交付都沿用本清单格式，明确文件、行为、验证和限制。

| 文件 | 实际修改 | 用户可见行为 |
|---|---|---|
| app/state.py（新增） | SQLite sessions/tasks/messages 三表，事务、版本检查、重复提交键、重启恢复 | 会话、证据和草稿不再随请求结束消失 |
| app/sessions.py（新增） | 创建/查询会话、补充、编辑草稿、创建/查询/取消任务 | 可以多轮处理同一 Issue，异步返回202后查询任务 |
| app/engine.py | continuation 业务上下文；补充优先进入检索查询；旧摘要/草稿标记为非证据 | 后续分析结合补充，重新读取 Issue 与检索，不无限拼接旧聊天 |
| app/api.py | 注册 V3 路由；lifespan 初始化、恢复、停止后台任务；数据库单进程锁 | 退出和重启有明确状态，health.version=0.3.0 |
| app/config.py、.env.example | 新增 STATE_DB_PATH，默认 work/sessions.sqlite3 | 可指定数据库保存位置 |
| tests/test_sessions.py（新增） | 12项状态、隔离、版本、幂等、取消、重启、预算、上下文与证据快照测试 | 验证新增业务边界 |
| tests/test_api.py | API测试使用各自临时数据库 | 不让测试修改实际演示数据库 |
| scripts/demo_v3.py（新增） | 两轮真实 API 演示，明确模拟补充，保存原始结果 | 可重复演示并检查409/404、任务复用和草稿 |
| pyproject.toml | 版本0.3.0，项目描述更新 | 标识当前版本 |
| README.md、docs/v3-*.md | 启动、手动操作、代码教学、实际失败与验证记录 | 可以解释设计并复现流程 |
| docs/v2-readme.md（新增存档） | 保留上版说明 | 可比较 V2 与 V3 |
| verification/v3-*.json/xml/txt | 保存实际测试、HTTP、重启和人工观察结果 | 区分程序验证与模型质量 |

未新增第三方包：使用 Python 内置 sqlite3；filelock 已由 V2 锁定。MCP 仍是原两个只读工具。V1/V2压缩包保持原样，参考仓库未修改。

行为变化需要留意：继续分析成功会生成新的当前草稿；人工编辑与上一轮模型原文分开保存。异步任务在浏览器关闭后继续，显式取消才停止。版本号过期、运行时编辑、重复键与内容版本不符均返回409。会话目标创建后固定，要处理另一个 Issue 应创建新会话。

验证：127项测试通过；真实两轮均completed，单轮2个MCP调用、3个模型请求；重启后完整会话一致。详见[v3-validation.md](v3-validation.md)。本次只实现V3，V4写入等待用户授权进入该版本。
